# Artist Report Generation Workflow

艺术家研究报告的核心生成规范：从艺术家身份确认开始，经多源检索、结构化事实抽取、冲突检查和引用核验，最终生成 JSON、可读报告与浏览器交付页面。

这个仓库只保留“生成报告”本身及轻量浏览器查看器，不包含完整 Web 产品、移动端、视频或后台业务系统。

> 当前版本是一套可实现的生成规范、JSON Schema 和参考样例，还不是已经接通搜索服务与模型 API 的一键运行程序。

## 生成流程

1. **身份消歧**：根据姓名、别名、出生年份、媒介、地区和稳定标识确认目标艺术家，禁止仅凭同名合并记录。
2. **来源检索**：优先检索艺术家官方资料、博物馆与公共机构、画廊、展览机构和拍卖行原始记录。
3. **证据登记**：保存来源 URL、标题、发布或访问时间、来源层级，以及支持具体陈述的证据。
4. **结构化抽取**：先把身份、创作、展览、机构收藏、画廊代理和公开市场事实写入固定 schema。
5. **覆盖与冲突检查**：为缺失、有限或互相矛盾的数据设置明确状态，不用推测补齐空白。
6. **叙述生成**：只在事实抽取后生成概览与分析；区分艺术家陈述、机构/画廊解释、独立评论和系统综合。
7. **质量检查**：检查身份、日期、分类、引用、schema、禁用投资语言和无证据结论。
8. **交付**：输出结构化 JSON、Markdown 和浏览器报告，并标注生成时间、信息截止日期、版本与资料覆盖状态。

## 输入与输出

最小输入：

- 艺术家姓名；
- 用户确认的艺术家实体；
- 可选的别名、国家/地区、媒介或画廊信息，仅用于消歧。

输出：

- 符合 schema 的结构化艺术家报告；
- 带行内引用/来源登记的可读报告；
- 可切换中英文、保存状态并导出 PDF 的浏览器报告；
- 冲突、资料缺口、市场数据限制和信息截止日期。

## 浏览器查看与保存 PDF

查看器保留原报告的杂志式长页 UI：黑白封面、荧光黄信息条、蓝色展览章节、作品卡、市场卡和参考文献版式。默认打开中文，可即时切换英文；“保存 PDF”会打开浏览器打印面板，并使用 A4 打印样式。

```bash
cd viewer
npm install
npm run dev
```

浏览器打开页面后即可检查。导出时选择系统打印面板中的“保存为 PDF”。导出的 PDF 只包含当前选中的语言，工具栏不会出现在成品里。

## 产品边界

报告不提供作品鉴定、单件作品估值、买卖建议或价格上涨预测，也不能替代法律、税务、保存修复或专业尽调。付费艺术市场数据库的数据不得在没有相应 API 或商业授权时自动化再分发。
